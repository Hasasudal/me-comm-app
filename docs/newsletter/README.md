# 뉴스레터 메일 발송 설정 안내

미컴 라운지 뉴스레터는 **관리자 Gmail 계정**에서 발송됩니다.
Google Apps Script(구글이 제공하는 무료 스크립트 서비스)에 작은 프로그램(`Code.gs`)을 올려 두고,
사이트 서버(Cloudflare)가 그 프로그램을 불러 메일을 보내는 방식입니다.

처음 한 번만 설정하면 되고, 20~30분 정도 걸립니다.

> 화면의 메뉴 이름은 구글이 수시로 바꾸기 때문에 아래 안내와 조금 다를 수 있습니다. 비슷한 이름의 버튼을 찾으면 됩니다.

---

## 0. 뉴스레터 전용 Gmail 계정 준비 (권장)

개인이 평소 쓰는 Gmail 말고, **뉴스레터만 보내는 전용 Gmail 계정**을 새로 만들어 쓰는 것을 권장합니다.
비밀값이 새거나 스크립트가 잘못 쓰이더라도 개인 메일·드라이브까지 위험해지지 않습니다.

- **2단계 인증**을 꼭 켭니다. 가능하면 **패스키**나 **보안 키**를 쓰세요. (문자 인증보다 안전합니다)
- **복구 이메일·복구 전화번호**를 등록해 둡니다. 잠기면 뉴스레터를 보낼 수 없습니다.
- 학교 계정(@ks.ac.kr)은 3단계에서 막히는 경우가 있으니 **개인 Gmail(@gmail.com)**로 만드세요.
- 계정 비밀번호는 운영진 중 꼭 필요한 사람만 알고 있게 합니다.

아래 안내의 "관리자 Gmail 계정"은 이 전용 계정을 뜻합니다.

## 1. 스크립트 프로젝트 만들기

1. 뉴스레터를 보낼 **관리자 Gmail 계정**으로 로그인한 상태에서 <https://script.google.com> 에 들어갑니다.
2. 왼쪽 위 **새 프로젝트**를 누릅니다.
3. 맨 위 "제목 없는 프로젝트"를 눌러 이름을 `미컴 뉴스레터`처럼 바꿉니다.
4. 편집 화면에 있는 기본 코드(`function myFunction() { ... }`)를 **모두 지우고**,
   이 폴더의 `Code.gs` 내용을 통째로 복사해 붙여 넣습니다.
5. 저장 아이콘(디스크 모양)을 누르거나 `Ctrl + S`로 저장합니다.
6. **권한 줄이기(매니페스트 붙여 넣기)**: 스크립트가 "메일 보내기" 권한만 갖도록 설정 파일을 넣습니다.
   1. 왼쪽 톱니바퀴 **프로젝트 설정** → **"편집기에서 'appsscript.json' 매니페스트 파일 표시"**(대략 이런 이름)에 체크합니다.
   2. 왼쪽 **편집기**(`< >` 모양)로 돌아가면 파일 목록에 `appsscript.json`이 보입니다. 눌러서 내용을 **모두 지우고**,
      이 폴더의 `appsscript.json` 내용을 통째로 붙여 넣은 뒤 저장합니다.
   - 이 파일은 시간대(서울), 메일 발송 권한만 쓰기, 웹 앱 설정(실행: 나 / 액세스: 모든 사용자)을 정해 둡니다.
   - 나중에 2단계에서 승인 창이 뜰 때 권한 목록에 **"이메일 보내기"** 하나만 보이면 제대로 들어간 것입니다.
   - 실행할 때 "권한이 없습니다"류의 오류가 나면 매니페스트가 잘못 붙여 넣어진 것이니 다시 붙여 넣으세요.

## 2. `setup` 실행해서 비밀값 만들기

비밀값은 "우리 사이트 서버만 이 스크립트를 쓸 수 있게" 해 주는 비밀번호 같은 것입니다.

1. 편집 화면 위쪽의 함수 선택 칸에서 **`setup`**을 고르고 **실행**을 누릅니다.
2. "승인 필요" 창이 뜨면 **권한 검토** → 관리자 계정을 선택합니다.
3. **"Google에서 확인하지 않은 앱"**(또는 "확인되지 않은 앱") 경고가 나옵니다.
   직접 만든 스크립트라 구글 심사를 받지 않았기 때문에 나오는 정상적인 경고입니다.
   왼쪽 아래 **고급** → **(프로젝트 이름)(으)로 이동(안전하지 않음)**을 누릅니다.
4. "이메일 보내기" 등의 권한 목록이 나오면 **허용**을 누릅니다.
5. 아래쪽 **실행 로그** 맨 끝 `[NEWSLETTER_SCRIPT_SECRET]` 뒤에 긴 영문·숫자 문자열(64자)이 찍힙니다. 이 값이 **비밀값**입니다.
   다른 사람에게 보여 주지 마세요.
   - 로그에 "ALLOWED_DOMAINS가 비어 있어 ks.ac.kr로 설정했습니다"도 함께 보일 수 있습니다. 정상입니다 (5단계에서 확인).
   - **실행 로그는 프로젝트에 남습니다.** 나중에 **실행** 메뉴에서 이 실행을 열면 비밀값이 다시 보입니다.
     그래서 프로젝트는 소유자(관리자 계정)만 볼 수 있어야 합니다. 혹시 프로젝트를 다른 사람과 공유한 적이 있다면,
     공유를 끊은 뒤 `setup`을 다시 실행해 비밀값을 바꾸세요 (9단계 "비밀값을 바꾸고 싶을 때").
   - **파일로 저장하지 마세요.** 프로젝트 폴더는 OneDrive로 동기화되기 때문에, 폴더 안에 메모 파일을 만들면 클라우드에도 올라갑니다.
   - 4단계에서 `wrangler secret put`이 값을 물어볼 때 **로그에서 바로 복사해 붙여 넣는 것**이 가장 안전합니다.
   - 어쩔 수 없이 잠깐 메모장 등에 적어 뒀다면, Cloudflare에 넣은 뒤 **바로 지우세요.** (휴지통도 비우기)

> 로그를 놓쳤다면 `setup`을 다시 실행하면 됩니다. 다만 실행할 때마다 비밀값이 **새로 바뀝니다**.

## 3. 웹 앱으로 배포하기

1. 오른쪽 위 **배포** → **새 배포**를 누릅니다.
2. "유형 선택" 옆 톱니바퀴를 눌러 **웹 앱**을 고릅니다.
3. 다음처럼 설정합니다. (항목 이름은 대략 이렇습니다)
   - 설명: 아무거나 (예: `뉴스레터 v1`)
   - **다음 사용자 인증 정보로 실행: 나** (관리자 계정)
   - **액세스 권한이 있는 사용자: 모든 사용자**
4. **배포**를 누르고, 권한을 다시 물으면 2단계처럼 허용합니다.
5. 나오는 **웹 앱 URL**을 복사합니다. `https://script.google.com/macros/s/.../exec` 처럼 **`/exec`로 끝나야** 합니다.
   (`/dev`로 끝나는 주소는 테스트용이라 사이트에서 쓸 수 없습니다.)

**왜 '모든 사용자'인가요?**
Cloudflare 서버는 구글 로그인을 할 수 없기 때문에, '모든 사용자'로 열어 두지 않으면 호출 자체가 막힙니다.
대신 스크립트가 2단계의 **비밀값이 맞는 요청만** 처리하므로, 주소를 아는 사람이 있어도 메일을 보낼 수는 없습니다.

**'모든 사용자'가 선택지에 없다면?**
학교·회사(Google Workspace) 계정이라 관리자가 외부 공개를 막아 둔 것입니다. 이 경우 0단계의 **전용 개인 Gmail 계정**으로 1단계부터 다시 하세요.
(예전에 학교 계정으로 배포했다가, 사이트가 JSON 대신 구글 로그인 화면을 받아 **"메일 발송 서버에 연결하지 못했습니다"**가 뜬 적이 있습니다.)

**확인:** 복사한 URL을 **시크릿 창**(로그인 안 된 브라우저 창, `Ctrl + Shift + N`)의 주소창에 붙여 넣으면
`{"ok":true,"service":"micom-newsletter"}`가 보여야 합니다.
구글 로그인 화면이나 "권한 필요" 화면이 나오면 액세스 권한이 '모든 사용자'가 아닌 것입니다.
(평소 창에서 열면 이미 로그인돼 있어서 문제가 있어도 정상처럼 보일 수 있습니다.)

## 4. Cloudflare에 두 값 넣기

컴퓨터에서 명령 프롬프트(또는 PowerShell)를 열고, **반드시 `web` 폴더 안으로 이동한 뒤** 실행합니다.

```
cd "C:\Users\pdapp\OneDrive\바탕 화면\미컴 앱\web"
npx wrangler secret put NEWSLETTER_SCRIPT_URL --config wrangler.jsonc
npx wrangler secret put NEWSLETTER_SCRIPT_SECRET --config wrangler.jsonc
```

- 명령마다 값을 입력하라고 물어봅니다.
  - `NEWSLETTER_SCRIPT_URL` → 3단계의 웹 앱 URL (`/exec`로 끝나는 주소)
  - `NEWSLETTER_SCRIPT_SECRET` → 2단계의 비밀값
- 붙여 넣은 값은 화면에 보이지 않을 수 있습니다. 붙여 넣고 그냥 Enter를 누르면 됩니다.
- **주의:** 상위 폴더(`미컴 앱`)에서 실행하면 `wrangler.jsonc`를 찾지 못하거나 엉뚱한 곳에 저장됩니다. 예전에 이 실수가 있었으니 꼭 `web` 폴더에서 실행하세요.

## 5. 받는 사람 도메인 제한 확인: `ALLOWED_DOMAINS` (필수)

회원은 모두 학교 이메일(@ks.ac.kr)로 가입하므로, 스크립트가 **@ks.ac.kr 주소로만** 메일을 보내도록 **반드시** 막아 둡니다.
혹시 비밀값이 새더라도, 그 값을 가진 사람이 아무에게나(스팸 등) 메일을 보낼 수 없게 되어 피해가 줄어듭니다.

2단계의 `setup`이 값이 비어 있으면 자동으로 `ks.ac.kr`을 넣어 줍니다. 그래도 아래처럼 **직접 확인**하세요.
(예전에 설치해서 `setup`을 다시 돌리지 않은 경우에는 값이 없을 수 있습니다. 그때는 직접 추가합니다.)

1. 스크립트 편집 화면 왼쪽의 톱니바퀴 **프로젝트 설정**을 누릅니다.
2. 아래쪽 **스크립트 속성**에 `ALLOWED_DOMAINS` = `ks.ac.kr`이 있는지 봅니다.
   없으면 **스크립트 속성 추가**(대략 이런 이름)를 눌러 속성: `ALLOWED_DOMAINS`, 값: `ks.ac.kr` 을 넣고 **저장**합니다.
   - 여러 도메인을 허용하려면 쉼표로 구분합니다. 예: `ks.ac.kr,gmail.com`
   - 같은 화면에 `NEWSLETTER_SECRET`도 보이는데, **그 값은 건드리지 마세요.**
3. 저장 즉시 적용됩니다. 재배포는 필요 없습니다.

허용되지 않은 주소는 보내지 않고 "잘못된 주소"로 처리됩니다.
(속성을 지우거나 비워 두면 제한 없이 보내게 되니, 비워 두지 마세요.)

## 6. 사이트에서 테스트 발송

1. 사이트에 관리자로 로그인 → **뉴스 승인** → **뉴스레터** 화면으로 갑니다.
2. **나에게 테스트 발송**을 누릅니다.
3. 관리자 메일함에 뉴스레터가 도착하면 설정 완료입니다. (스팸함도 확인해 보세요.)

> 5단계 때문에 테스트 메일도 **@ks.ac.kr 주소로만** 갑니다.
> 관리자 사이트 계정의 이메일이 다른 도메인이면 테스트 발송이 "잘못된 주소"로 실패하니 참고하세요.

## 7. 알아 둘 제한

- **하루 발송량**: 개인 Gmail 계정은 Apps Script로 **하루 약 100명**에게 보낼 수 있습니다.
  (Google Workspace 학교·회사 계정은 보통 1,500명 정도로 더 많습니다. 갓 만든 계정은 더 적게 잡힐 수 있습니다.)
  - 받는 사람 1명 = 1건으로 셉니다.
  - 한도는 첫 발송 후 약 24시간이 지나면 다시 채워집니다. 정확한 초기화 시각은 구글이 정합니다.
- 구독자가 한도보다 많으면 그날은 보낼 수 있는 만큼만 보내고 멈춥니다.
  **다음 날 '이어서 보내기'**를 누르면 못 받은 사람에게만 이어서 보냅니다.
- **예약 발송**은 Cloudflare의 예약 작업(cron)이 **10분마다** 확인해서 보냅니다. Apps Script 쪽에 따로 설정할 것은 없습니다.
  - 예약 시각이 되면 이 스크립트를 불러 묶음으로 보내고, 하루 한도를 다 쓰면 다음 날 실행에서 자동으로 이어서 보냅니다.
  - 그래서 스크립트의 **실행** 목록에 `doPost`가 10분 간격으로 찍힐 수 있습니다. **보낼 예약이 있을 때만** 불리고,
    예약이 없으면 스크립트를 부르지 않으니 평소에는 늘지 않습니다. (8단계의 "가끔 두 곳을 확인하세요"를 볼 때 참고하세요)
- 남은 발송량은 스크립트 편집 화면에서 `testQuota`를 실행하면 실행 로그에서 볼 수 있습니다.
- 메일은 **관리자 Gmail 주소**로 발송되고 보낸 사람 이름은 "미컴 라운지"로 표시됩니다.
  구독자가 답장하면 관리자 Gmail로 옵니다.
- 보낸 메일은 관리자 Gmail의 **보낸편지함**에도 남습니다.
- 본문이 너무 크면(약 180KB 이상) 보내지 않습니다. 한글은 글자당 3바이트라 생각보다 빨리 찹니다.

## 8. 보안 주의 사항

- **스크립트 프로젝트를 다른 사람과 공유하지 마세요.** (공유 버튼으로 편집자 추가 금지)
  편집 권한이 있는 사람은 비밀값을 볼 수 있고, 코드를 고쳐 관리자 계정 이름으로 아무 메일이나 보낼 수 있습니다.
- **실행 로그에 비밀값이 남습니다** (2단계 참고). 프로젝트를 소유자만 볼 수 있게 두고, 공유한 적이 있다면 `setup`을 다시 실행해 비밀값을 바꾸세요.
- **안 쓰는 배포는 보관(끄기)하세요.** 예전에 만든 웹 앱 주소(`/exec`)도 지우지 않는 한 **계속 살아 있고, 같은 비밀값으로 메일을 보낼 수 있습니다.**
  - **배포** → **배포 관리** → 왼쪽 목록에서 지금 Cloudflare에 넣은 것 **말고** 다른 배포를 고르고 → **보관**(대략 이런 이름)을 누릅니다.
  - 어떤 배포가 지금 쓰는 것인지는 4단계에서 넣은 URL과 비교하면 됩니다.
  - 9단계처럼 "새 버전"으로 고치면 주소가 그대로라 배포가 늘지 않습니다. **새 배포**를 누를 때마다 주소가 하나씩 늘어나니, 그랬다면 예전 것을 보관하세요.
- **예전에 학교 계정(@ks.ac.kr)으로 만든 스크립트 프로젝트가 있다면 지우세요.** (3단계 참고)
  그 계정으로 <https://script.google.com> 에 들어가 해당 프로젝트의 **⋮(더보기)** → **삭제**(대략 이런 이름). 지우기 전에 배포를 먼저 보관해 두면 더 확실합니다.
- **가끔 두 곳을 확인하세요.**
  1. 관리자 Gmail의 **보낸편지함**: 내가 보내지 않은 메일이 있는지
  2. 스크립트 편집 화면 왼쪽 **실행**(목록 모양 아이콘, 대략 이런 이름): `doPost`가 내가 발송하지 않은 시간에 실행됐는지, 실패가 잔뜩 쌓여 있는지
     (실패가 많으면 누군가 비밀값을 맞춰 보려고 한 것일 수 있습니다)
- 보낸편지함이나 실행 목록에 이상한 기록이 보이면 비밀값이 샜을 수 있습니다. **바로**
  1. 스크립트에서 `setup`을 다시 실행해 비밀값을 바꾸고 (예전 값은 즉시 쓸 수 없게 됩니다)
  2. 아래 9단계의 "비밀값을 바꾸고 싶을 때"대로 새 값을 Cloudflare에 다시 넣으세요.
  3. 전용 계정의 비밀번호도 바꾸고, 구글 계정의 **보안 → 최근 보안 활동**(대략 이런 이름)을 확인하세요.

## 9. 나중에 바꿀 때

**이번 `Code.gs` 업데이트를 반영할 때 (이미 설치한 경우)**
1. 이 폴더의 새 `Code.gs` 내용으로 스크립트 편집 화면의 코드를 통째로 바꿔 붙여 넣고 저장합니다.
2. 1단계 6번처럼 `appsscript.json`도 이 폴더의 내용으로 바꿔 붙여 넣고 저장합니다.
3. 함수 선택 칸에서 `testQuota`를 한 번 실행합니다. 승인 창이 뜨면 2단계처럼 허용합니다. (`setup`은 비밀값이 바뀌니 필요할 때만)
4. 5단계대로 `ALLOWED_DOMAINS` = `ks.ac.kr`이 있는지 확인하고, 없으면 추가합니다.
   (값이 없어도 예전처럼 제한 없이 동작은 하지만, 꼭 넣으세요.)
5. 바로 아래 "스크립트 코드를 고쳤을 때"대로 **새 버전으로 배포**해야 적용됩니다. (URL은 그대로입니다)
6. 8단계대로 안 쓰는 배포는 보관하고, 예전 학교 계정 프로젝트가 있으면 지웁니다.

**스크립트 코드를 고쳤을 때**
저장만 해서는 사이트에 반영되지 않습니다.
**배포** → **배포 관리** → 기존 배포의 연필(수정) 아이콘 → 버전에서 **새 버전** 선택 → **배포**.
이렇게 하면 웹 앱 URL은 **그대로** 유지되므로 Cloudflare 설정은 다시 할 필요가 없습니다.
(**새 배포**를 누르면 **새 URL이 하나 더 생기고, 예전 URL도 그대로 살아 있습니다.** 그 경우 4단계의 URL을 다시 넣고, 예전 배포는 8단계대로 보관하세요.)

**비밀값을 바꾸고 싶을 때** (유출이 의심될 때 등)
1. 스크립트에서 `setup`을 다시 실행 → 새 비밀값 복사
2. `web` 폴더에서 `npx wrangler secret put NEWSLETTER_SCRIPT_SECRET --config wrangler.jsonc` 실행 → 새 값 입력
(비밀값은 저장 즉시 적용되므로 재배포는 필요 없습니다. 두 단계 사이에는 발송이 실패할 수 있습니다.)

## 10. 문제가 생겼을 때

**"메일 발송 서버에 연결하지 못했습니다"가 뜰 때**
- `NEWSLETTER_SCRIPT_URL`이 `/exec`로 끝나는 웹 앱 주소가 맞는지 확인 (3단계의 "확인" 방법으로 **시크릿 창**에서 열어 보기)
- 배포할 때 액세스 권한을 **모든 사용자**로 했는지 확인 (배포 관리에서 볼 수 있음).
  선택지에 없었다면 학교 계정이라 막힌 것이니 전용 개인 Gmail로 다시 설치합니다 (3단계 참고)
- 코드를 고친 뒤 **새 버전으로 배포**하지 않았는지 확인 (9단계)
- 비밀값이 틀린 경우에도 발송이 거부됩니다. 의심되면 9단계대로 비밀값을 다시 맞춥니다.

**"메일 발송 결과를 확인하지 못했습니다. Gmail 보낸편지함을 확인해주세요."가 뜰 때**
- 메일을 묶음으로 보내는 도중 응답이 끊겨서, 그 묶음이 **실제로 나갔는지 사이트가 알 수 없는** 상태입니다.
- 이 묶음의 받는 사람은 일단 **실패로 표시**되고, 중복 발송을 막기 위해 **자동으로 다시 보내지 않습니다.**
- 다시 보내기 전에 관리자 Gmail의 **보낸편지함**을 먼저 확인하세요. 이미 나간 메일이면 다시 보내지 않아도 됩니다.

**특정 사람만 "잘못된 주소"로 실패할 때**
- 5단계의 `ALLOWED_DOMAINS`에 없는 도메인(예: @gmail.com)이면 일부러 보내지 않은 것입니다.

**오늘 발송 한도를 다 썼다고 나올 때**
- 정상입니다. 약 하루 뒤 **이어서 보내기**를 누르세요.

**메일이 스팸함으로 갈 때**
- 구독자에게 관리자 Gmail 주소를 **연락처에 추가**하거나 "스팸 아님"을 눌러 달라고 안내하세요.
- 짧은 시간에 아주 많이 보내거나, 링크·이미지만 가득한 메일은 스팸으로 분류되기 쉽습니다.

## (개발자용) 로컬 테스트

로컬 개발 환경에서는 실제 Gmail 대신 가짜 발송 서버(`scripts/test-newsletter.mjs`)를 씁니다.
`web/.dev.vars`에 다음을 넣고, 가짜 서버를 띄운 상태에서 개발 서버를 실행합니다.

```
NEWSLETTER_SCRIPT_URL=http://127.0.0.1:5199
NEWSLETTER_SCRIPT_SECRET=local-newsletter-secret
```

요청/응답 형식은 `Code.gs`의 `doPost`와 같습니다.
