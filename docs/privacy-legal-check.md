## 1. 우리 사이트가 다루는 개인정보 (코드 기준)

| 항목 | 언제 | 저장 위치 |
|---|---|---|
| 학교 이메일, 이름(운영진에게만 보임) | 가입 | Firebase Auth, D1 `users` |
| 비밀번호 | 가입 | Firebase만(우리 DB에는 없음) |
| Firebase uid, 인증 시각, 상태·직책 | 로그인·관리 | D1 `users` |
| 세션 | 로그인 | 쿠키 `micom_session`, D1 `sessions`(해시만) |
| IP | 요청 제한 | D1 `attempts`에 해시만, 원본 IP 저장 안 함 |
| 글·댓글·별명·문의·건의·기사 | 글쓰기 | D1 `posts`, `comments` |
| 사진 | 업로드 | R2 `micom-images`(EXIF 제거), D1 `images` |
| 뉴스레터 수신 여부·수신거부 토큰·발송 기록 | 가입·발송 | D1 `users`, `newsletters`, `newsletter_deliveries` |
| 관리 감사 로그(처리자·대상 이름·이메일) | 직책·정지·승인·거절 | D1 `member_audit` |
| 백업 | 매주 월 03:00 | R2 `micom-backups`(D1 전체, 평문 SQL) |

분석·광고 쿠키나 추적 스크립트는 없습니다. 쿠키는 로그인용 `micom_session` 하나이고, 나머지는 테마·임시저장 같은 기능용 브라우저 저장소입니다.

## 2. 항목별 상세

### 2-1. 처리방침 (제30조) — 🔴 없음
- 사이트 어디에도 개인정보 처리방침과 이용약관 페이지, 링크가 없습니다.
- 처리방침에 들어가야 할 것: 처리 목적, 항목, 보유기간, 제3자 제공, 위탁, 국외 이전, 파기 방법, 정보주체 권리와 행사 방법, 안전성 확보조치, 쿠키 운영과 거부 방법, CPO 이름·연락처, 고충 처리 창구, 변경 이력, 동의 없이 처리하는 근거.
- "개인정보 처리방침"이라는 이름으로 모든 페이지(푸터나 사이드바)에서 바로 보이게 걸어야 합니다.
- 작성 도구: 개인정보 포털(privacy.go.kr)의 처리방침 만들기.

### 2-2. 개인정보 보호책임자 (제31조) — 🔴 없음
- 지금은 학과 사무실과 미컴봇 안내뿐입니다. 운영진 한 명을 CPO로 정해 처리방침에 이름과 연락 이메일을 적는 게 안전합니다.
- 학생 단체가 "소상공인 등 대표자 간주" 완화 대상인지는 [불확실]입니다.

### 2-3. 수집 근거와 동의 (제15조, 제22조) — 🟡 일부
- 가입과 커뮤니티 이용에 꼭 필요한 이메일, 이름, 글은 "계약 이행"(제15조 제1항 제4호)으로 동의 없이 처리할 수 있습니다. **단 처리방침에 그 근거를 적어야 합니다.**
- **문제: 뉴스레터가 기본 수신(`newsletter=1`)입니다.** 뉴스레터는 가입에 꼭 필요한 처리가 아니어서 선택 동의 대상으로 보는 게 맞습니다.
  - 가입 화면에는 "뉴스레터가 발송된다"는 안내 한 줄뿐이고 체크박스가 없습니다(`app/signup/signup-form.tsx`).
  - 미인증 가입은 0으로 시작하다가, 인증 로그인 때 동의 없이 1로 바뀝니다(`lib/member-auth.ts`).
- 고칠 방향: 가입 화면에 "뉴스레터 받기(선택)" 체크박스, 기본값은 해제. 기존 회원은 다음 로그인 때 한 번 묻기.

### 2-4. 처리위탁과 국외 이전 (제26조, 제28조의8) — 🔴 공개 없음
| 받는 곳 | 넘어가는 정보 | 성격 |
|---|---|---|
| Google (Firebase Auth) | 이메일, 이름, 비밀번호, 인증 메일 | 위탁 + 국외 이전 |
| Google (Apps Script·Gmail) | 뉴스레터 수신자 이메일, 제목, 본문 | 위탁 + 국외 이전, 관리자 Gmail 보낸편지함에 이력 남음 |
| Google Fonts, reCAPTCHA | 방문자 IP(브라우저가 직접 접속) | 자동 수집 |
| Cloudflare (Workers, D1, R2) | 서비스 데이터 전부 | 위탁 + 국외 이전(서버 위치 [미확인]) |
| 카카오·노션 | 링크만, 데이터 전달 없음 | 해당 없음 |
- 2023 개정 이후 "계약 이행에 필요한 위탁·보관"이면 처리방침에 공개하는 것만으로 동의 없이 국외 이전이 가능합니다. 대신 처리방침에 **이전 항목, 국가, 시기·방법, 받는 회사와 연락처, 목적, 보유기간, 거부 방법**을 적어야 합니다.

### 2-5. 보유기간과 파기 (제21조) — 🟡 일부
- 잘 되어 있는 것: 세션 14일, 요청 제한 기록 자동 삭제, 미첨부 사진 1일 뒤 정리, 탈퇴 시 문의·건의·미공개 기사·세션·발송 기록·계정 삭제와 글·댓글 익명화.
- 빈 곳:
  - **백업**: 탈퇴해도 R2 백업에 이메일 등이 최대 180일 남습니다. 그런데 180일 만료 규칙이 버킷에 실제로 설정됐는지는 [미확인]입니다(Cloudflare 대시보드 확인 필요). 처리방침에 "백업은 최대 180일 보관 후 삭제"라고 적고, 복구했을 때 탈퇴자를 다시 지우는 절차를 문서로 남겨야 합니다.
  - **감사 로그 `member_audit`**: 정리 코드가 없어 무기한 보관됩니다. 특히 **관리자가 거절한 가입 신청자의 이름·이메일이 영구히 남습니다.** 보관기간(예: 3년)을 정하고 지나면 지우거나 익명화해야 합니다.
  - **미인증 대기 계정**: 30일 지난 대기 계정은 "다음 미인증 로그인이 있을 때" 지워집니다. 크론으로 주기 삭제하는 게 맞습니다.
  - **뉴스레터 발송 기록**: 보관 기한이 없습니다.
  - **탈퇴 후 남는 uid**: `images.owner_id`, `clubs.requested_by`, `newsletters`의 작성·발송자 id와 이름이 익명화되지 않습니다.
- 1년 미이용자 휴면 파기 의무는 2023 개정으로 없어졌습니다. 자체 보유기간을 정해 처리방침에 적으면 됩니다.

### 2-6. 정보주체 권리 (제35~38조) — 🟡 일부
- 있음: 계정 페이지에서 이름·이메일·비밀번호·뉴스레터 설정 변경, 회원 탈퇴, 메일 속 로그인 없는 수신거부.
- 없음: 처리방침에 행사 방법 안내, 열람·삭제 요청 창구(CPO 이메일). 요청은 원칙적으로 10일 안에 처리해야 합니다.
- 탈퇴 때 Firebase 계정 삭제가 실패할 수 있고, 이때 학과 사무실에 알리라고만 안내합니다. 처리 담당을 정해 두세요.

### 2-7. 안전성 확보조치 (제29조, 고시) — 🟡 일부
- 충족: 접근권한 분리(관리자, 학사·학생회 담당), 비밀번호는 Firebase가 보관하고 글 비밀번호는 일방향 해시(PBKDF2), 세션은 해시 저장, HTTPS 강제(HSTS), 로그에 이메일을 남기지 않음.
- 빈 곳:
  - **접속기록**: 고시는 개인정보취급자(운영진)의 접속기록을 1년 이상 보관하고 월 1회 이상 점검하라고 합니다. 지금 `member_audit`은 직책·정지·승인만 기록하고, **관리자가 회원 이메일이나 작성자 정보를 조회한 기록은 없습니다.**
  - 권한 변경 기록은 3년 보관 대상입니다. 지금은 남지만 보관기간이 정해져 있지 않습니다.
  - 학사·학생회 담당자가 문의·건의 작성자의 이름·이메일을 봅니다. 글쓰기 화면은 "관리자만 볼 수 있다"고 안내해서 **고지 내용과 실제가 다릅니다.** 11월 10일 stash의 변경(작성자 신원은 관리자만)이 이걸 바로잡습니다.
  - 소규모 사업자 완화 범위(내부관리계획 등)의 세부 기준은 [불확실]입니다.

### 2-8. 유출 통지·신고 (제34조) — 🔴 절차 없음
- 유출을 알게 되면 **72시간 안에** 해당 회원에게 알려야 하고, 1명만 유출돼도 통지 대상입니다.
- 해킹으로 인한 유출은 규모와 상관없이 개인정보위나 KISA에 72시간 안에 신고해야 합니다.
- 할 일: 누가 판단하고, 누가 회원에게 메일을 보내고, 어디에 신고하는지 한 장짜리 대응 절차를 `docs/`에 만들어 두기.

### 2-9. 뉴스레터와 광고성 정보 (정보통신망법 제50조) — ⚪/🟡
- 제50조는 "영리 목적의 광고성 정보"에만 적용됩니다. 학과 소식·행사·학사 공지 위주인 지금 뉴스레터는 해당하지 않을 가능성이 높습니다. 비영리 공지성 메일을 직접 다룬 해석은 찾지 못했습니다 [불확실].
- **스폰서 홍보, 유료 행사 판매, 제휴 할인이 섞이면 해당**할 수 있고, 그러면 아래가 전부 필요합니다(지금 코드에는 하나도 없음):
  - 사전 명시적 수신 동의(기본 수신이면 안 됨)
  - 제목 앞 "(광고)"와 발신자 이름·연락처
  - 2년마다 수신 동의 확인
  - 밤 9시~아침 8시 발송은 별도 동의
- 권장: "뉴스레터에 영리 광고를 넣지 않는다"는 운영 원칙을 정해 두고, 수신은 선택 동의로 바꾸기. 수신거부 링크는 이미 있습니다.

### 2-10. 게시판 (정보통신망법 제44조의2) — 🟡
- 임시조치 의무는 영리 목적 정보통신서비스 제공자 대상이라 비영리 학생 커뮤니티에 법적 의무가 있는지는 [불확실]입니다.
- 그래도 권리침해(명예훼손 등) 신고 창구와 게시 중단 절차를 도움말에 두면 운영진 책임을 줄이는 데 도움이 됩니다.
- 인터넷 실명제(제44조의5)는 2012년 위헌 결정으로 효력이 없습니다. 학교 메일 인증은 법정 의무가 아니라 서비스 정책입니다.

## 3. 우선순위

1. **개인정보 처리방침 페이지**: 위 2-1 항목 전부, 특히 위탁·국외 이전(Google, Cloudflare), 보유기간(백업 180일 포함), 쿠키, CPO. 모든 페이지에서 링크.
2. **뉴스레터 선택 동의로 전환**: 가입 체크박스(기본 해제), 기존 회원 재확인.
3. **문의·건의 작성자 신원 고지 불일치 해소**: stash 변경 적용 또는 안내 문구 수정.
4. **보관기간 정리**: 감사 로그·거절된 신청자·발송 기록 보관기간 정하고 크론으로 파기, 대기 계정 주기 삭제, 탈퇴 시 남는 uid 익명화.
5. **유출 대응 절차 문서**(72시간).
6. **관리자 개인정보 조회 기록**(1년 보관) 추가 검토.
7. Cloudflare 대시보드에서 확인: R2 백업 버킷 180일 수명 규칙, 버킷 공개 접근 꺼짐, D1·R2 리전.
